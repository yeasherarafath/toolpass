Full Business Description
This business is a digital tool subscription access management business.
The owner/admin manages premium online tools, software subscriptions, team workspaces, shared accounts, invite-only accounts, and manual-access products. Then the business sells access to customers as either single-tool products or multi-tool bundles.
The platform is built so the admin can manage the full business from one dashboard: tools, subscriptions, packages, customers, orders, payments, required customer information, access delivery, OTP/2FA requests, device limits, support tickets, renewals, and staff tasks.
The business is not just a normal ecommerce shop. It is an access management system for digital tools.
Simple One-Line Explanation
This is a platform where an admin sells access to premium digital tools, manages customer orders and payments, assigns tool access manually or automatically, handles invite-only tools, OTP/2FA, device limits, support, and renewals from one dashboard.

Full Customer Order Flow
Step 1: Customer Chooses Package
Customer selects a product.
Example:
Canva Team Invite - 30 Days

or:
SEO Bundle - 30 Days

Step 2: System Creates Order
The system creates an order:
Order number: ORD-10001
Customer: Rahim
Package: SEO Bundle
Payment status: pending
Order status: pending

If the package needs extra information:
required_info_status = pending

If not:
required_info_status = not_required

Step 3: Customer Submits Required Information
If the product has custom fields, the customer fills them.
Example:
Invite Email: rahim@example.com
Full Name: Rahim Ahmed

Then:
required_info_status = submitted

Admin reviews the information.
If correct:
required_info_status = approved

If wrong:
required_info_status = rejected

Customer may need to submit again.
Step 4: Customer Pays
Customer pays using a method like:
bKash
Nagad
Rocket
Bank
Card
Manual

Customer submits:
Transaction ID
Sender number
Payment screenshot

Payment status becomes:
pending

Admin verifies payment.
If valid:
payment_status = paid
payment record status = verified

If invalid:
payment_status = failed
payment record status = rejected

Step 5: System Checks If Order Is Ready
The order can be processed only when:
Payment status = paid

AND

Required information status = not_required OR approved

Then access creation can start.
Step 6: Access Is Created
For every tool in the package, the system/admin creates a user tool access record.
Example bundle:
SEO Bundle contains:
- Ahrefs
- Moz
- Semrush
- ChatGPT
- Canva Team

Access records:
Rahim -> Ahrefs
Rahim -> Moz
Rahim -> Semrush
Rahim -> ChatGPT
Rahim -> Canva Team

Each tool may have a different delivery method.
Step 7: Access Is Delivered
For credential or instruction tools:
delivery_status = delivered

For invite-only or manual tools:
delivery_status = pending

Admin task is created.
Example:
Task: Invite Rahim to Canva Team
Type: invite_user
Status: pending

When admin completes the invite:
delivery_status = delivered
delivered_at = now

OTP Security Rules
Admin should follow:
Store OTP encrypted
Auto-expire OTP quickly
Do not show expired OTP
Do not show 2FA secret to customers
Do not show backup codes to customers unless intentionally allowed
Log every OTP action
Rate-limit OTP requests
Only admin/staff can provide OTP

Business Rules
Order Processing Rule
Access should start only when:
payment_status = paid
AND
required_info_status IN (not_required, approved)

Access Creation Rule
For each tool in the package:
Create one user_tool_access record

Account Slot Rule
When a user is assigned to a tool account:
tool_accounts.used_slots increases by 1

When access expires or is revoked:
tool_accounts.used_slots decreases by 1

Account Full Rule
If:
used_slots >= max_users

Then:
tool account status = full

Delivery Rule
If tool access type is:
credential or instruction

Then access can be delivered.
If tool access type is:
invite or manual

Then admin task is needed.
OTP Rule
If tool/account requires OTP:
Customer can request OTP from dashboard.
Admin provides OTP.
OTP expires quickly.

Device Rule
If tool/account has device restriction:
Track devices.
Respect max device limit.
Require approval/reset if needed.

Renewal Rule
When order/access expires:
order_status = expired
user_tool_access.status = expired

Customer can renew.
If renewed:
New order is created
renewed_from_order_id stores previous order
Access date extends or new access is created

This business sells access to premium online tools. Customers can buy one tool or a bundle of tools. Some tools are delivered instantly, while others need admin action such as sending an invite, assigning an account, providing OTP, approving a device, or reviewing customer information. The admin dashboard manages everything: tools, accounts, packages, orders, payments, customer access, delivery status, OTP requests, device limits, support tickets, and renewals.
AI-Friendly Summary
The system is a digital subscription access management platform. Admin manages tools, tool accounts, packages, bundles, custom package fields, orders, payments, access records, manual delivery, invite-only delivery, OTP/2FA requests, device restrictions, support tickets, announcements, admin tasks, and activity logs. Customers buy packages, submit payment and required information, then receive access to one or multiple tools. Each access record tracks tool, account, delivery status, expiry, source, OTP needs, and device rules. Admin tasks are generated for manual work such as payment verification, required information review, invite delivery, OTP/2FA handling, device approval, device reset, and renewals.
